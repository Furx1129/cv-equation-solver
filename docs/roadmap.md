# 未来路线

后续工作主要分为三部分：完善无分类算式/算子识别，补充和整理测试数据，以及完善 UI 和计算接口。整体目标是让项目在展示时更稳定、更直观，也更容易说明每一步识别过程。

## 1. 无分类算式/算子识别

这是后续最主要的开发方向。当前 `auto` 模式已经可以根据图像结构选择识别链路，但还需要继续增强路由规则和易混淆情况判断。

重点任务：

- 调整 auto router 的结构打分规则，减少 `printed_basic`、`printed_2d_layout`、`handwritten_basic` 和 `calculus` 之间的误路由。
- 增强不同算式结构的判断，例如普通线性表达式、分数、上下标、根号、积分、导数和极限。
- 优化易混淆符号规则，例如 `x/×`、`0/o/O`、`1/l`、`5/s`、`6/b`、`9/g`、减号/分数线/等号。
- 在低置信度或候选分数接近时，完善多候选交叉验证逻辑。
- 输出更清楚的路由理由、候选分数和规则命中信息，方便调试和展示。

推进顺序：

1. 整理当前 auto 识别失败样例。
2. 按失败类型调整路由规则和符号消歧规则。
3. 用固定评估集验证修改前后的准确率和混淆矩阵。

## 2. 测试数据补充与整理

测试数据工作量相对较小，但对验证识别效果很关键。后续可以和 UI 展示工作一起推进。

重点任务：

- 补充真实拍照样例，包括不同光照、角度、背景、纸张边距和拍摄清晰度。
- 为新增样例补齐 `data/labels/` 下的标签文件，保持图片和标签同名。
- 按类别整理样例：印刷体四则运算、负数/小数、二维结构、手写符号、微积分样例。
- 保留一组稳定评估集，用于比较每次修改后的识别效果。
- 对失败样例记录原因，例如分割失败、符号混淆、结构识别错误或求解失败。

推荐输出：

- 新增样例图片和标签。
- 简短的数据说明。
- 一份稳定评估结果摘要，生成的 CSV 不提交到项目根目录。

## 3. UI 和计算接口

UI 目标是把现有 `run.py` 和识别 pipeline 包装成一个简单、可演示的图形界面。重点不是做复杂产品，而是让识别流程和结果更直观。

重点任务：

- 接入现有 `src/vision/pipeline.py`，支持选择图片并运行 `printed`、`handwritten`、`calculus` 和 `auto` 模式。
- 显示识别表达式、计算结果、错误信息和 warning。
- 显示必要的中间处理结果，例如归一化图、二值化图、字符分割框和 token 表。
- 在 auto 模式下展示路由类别、候选分数、结构特征和路由理由。
- 接入本地 `ArithmeticSolver` 和 `SymbolicSolver`，并处理 SymPy 未安装或 symbolic 求解失败的情况。

推进顺序：

1. 先保证单张图片上传、识别、计算、展示结果完整可用。
2. 再补充中间处理图和 token 表。
3. 最后补充 auto router 的调试信息展示。

## 当前优先顺序

1. 完善 auto 路由规则和易混淆符号判断。
2. 整理失败样例并补充少量真实拍照数据。
3. 打磨 UI 展示，把识别结果、计算结果和中间过程串起来。
4. 固化评估命令和摘要，避免生成文件污染项目根目录。
