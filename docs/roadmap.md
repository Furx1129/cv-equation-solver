# 未来路线

本文档记录项目后续可推进的方向。优先级以课程展示和可维护性为核心：先稳定现有传统图像处理链路，再扩展识别覆盖面，最后完善产品化接口。

## 近期目标

### 1. 固化评估基线

当前评估脚本已经可以输出分类结果、路由信息、候选分数和失败阶段。下一步应把评估流程变成固定基线：

- 明确每次评估使用的命令、代码版本和样例集范围。
- 在 `docs/evaluation.md` 中记录关键指标摘要，而不是提交整份生成 CSV。
- 为 auto router 保留稳定的混淆矩阵摘要。
- 将失败样例按 `segmentation`、`symbol`、`layout`、`solver` 分类复盘。

### 2. 提升二维结构识别

`printed_2d_layout` 是当前最值得继续优化的类别。建议优先处理：

- 分数线检测对短线、等号和减号的误判。
- 上标/下标与普通行内字符的区分。
- 根号覆盖范围判断。
- 多个二维结构混排时的递归解析。
- layout AST 到 plain text / SymPy 的一致性。

### 3. 改进手写符号鲁棒性

手写识别仍依赖少量样例和几何规则，适合继续做规则层面的增强：

- 扩展每类手写模板数量，保持 leave-one-out 评估。
- 单独维护常见混淆对，例如 `0/o/O`、`x/×`、`1/l`、`5/s`、`6/b`、`9/g`。
- 增加笔画粗细、倾斜、局部断裂等扰动测试。
- 将规则命中原因输出到调试报告，方便解释识别决策。

### 4. 修正求解后端选择

当前 `--backend auto` 需要更保守地判断何时使用 symbolic：

- 普通等式应优先交给 `ArithmeticSolver`，避免无必要依赖 SymPy。
- 只有出现变量、上标、函数、分式 AST、积分、导数、极限时才切到 symbolic。
- 当 SymPy 未安装时，CLI 和 UI 应给出明确提示和降级行为。

## 中期目标

### 1. 建立错误分析工作流

建议新增一个轻量错误分析文档或脚本：

- 从评估 CSV 汇总失败样例。
- 输出每个失败样例的原图、二值化图、分割框、token 表和候选分数。
- 将失败按模块归因，避免只看最终准确率。

### 2. 统一调试产物格式

目前 debug 输出分散在识别器和评估脚本中。后续可以统一为：

```text
debug/evaluation/<category>/<sample>/
├── normalized.png
├── binary.png
├── segments/
├── tokens.csv
├── layout.txt
└── decision.json
```

这样可以让单张识别、批量评估和 UI 调试共享同一套诊断格式。

### 3. 扩展表达式覆盖面

在不引入 OCR 或深度学习的前提下，可以逐步增加：

- 更多函数名：`sin`、`cos`、`tan`、`ln`、`log`、`exp`。
- 常量：`pi`、`e`、`∞`。
- 多字符变量和简单隐式乘法。
- 括号嵌套和多项式表达式。
- 更稳定的方程求解展示。

### 4. 强化测试分层

建议把测试明确分成几类：

- 单元测试：预处理、分割、匹配、序列化、求解。
- 回归测试：固定样例的识别结果不退化。
- 评估测试：完整数据集指标和混淆矩阵。
- 资源测试：模板、样例、标签完整性。

## 长期目标

### 1. API 和批处理能力

在 CLI 和 UI 稳定后，可以增加服务化接口：

- 单张图片 REST API。
- 批量目录识别。
- 返回 token、bbox、layout、warnings 和 solver result 的结构化 JSON。
- 明确区分识别错误和求解错误。

### 2. 更完整的 UI 工作流

Web UI 后续可以支持：

- 上传多张图片并批量处理。
- 展示 layout AST 或公式结构树。
- 点击 token 查看候选分数和规则命中原因。
- 导出识别结果和调试包。

### 3. 可选外部计算后端

识别模块仍保持传统图像处理方法；计算阶段可以作为可选能力接入外部系统：

- Wolfram Alpha 或类似计算 API。
- 更完整的 SymPy 化简和方程求解。
- 远程后端失败时回退到本地 solver。

外部后端只应处理已经识别出的表达式，不应替代图像识别流程。

## 非目标

以下内容不属于当前项目优先方向：

- 引入深度学习识别模型。
- 调用在线 OCR 或公式识别 API 完成识别。
- 为追求准确率牺牲可解释性。
- 把生成的评估 CSV 长期提交到版本库根目录。

## 推荐推进顺序

1. 先稳定评估基线和错误分析流程。
2. 集中提升 `printed_2d_layout` 的 layout 解析。
3. 增强手写混淆对规则和扰动测试。
4. 修正 backend auto 的求解器选择策略。
5. 统一 debug 产物格式。
6. 扩展 UI/API 和批处理能力。
